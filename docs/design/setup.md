# Setup
- **Position Rule.** `.setup-sections` places children by number: Budget, Rules, Categories (`:nth-child(3)`, spans all rows in column 2), Set-asides, Target split, Your own accounts, Settings, Your data. At 1800 px Budget and Categories span the five auto rows plus the flexible one so narrow sections stack in column 3. Adding or reordering a section means updating the grid in the same edit, and `SETUP_SECTIONS` in `pages/setup/sections.ts`: the jump row and the section ids (`budget`, `rules`, `categories`, `set-asides`, `target-split`, `own-accounts`, `month-start`, `your-data`) follow it by index, and Find's `/setup#id` places must name one of them (a test checks). A section that is still loading renders nothing, so ids are reassigned as sections appear; `start-day` is the field's own id.
- **The jump row** is eight chips under the top of the screen (`.setup-jump`, sticky, on the page ground so it reaches the edge on both sides). It never widens the page (`contain: inline-size`); sections keep `scroll-margin-top` clear of it. A jump to `#id`, from a chip or from Find, scrolls there (smooth unless reduced motion) and an arrival keeps it in place while sections above fill in, until the person scrolls.
- **Rules rows on a phone** use grid areas "pattern actions" / "cat actions" (editing: "pattern pattern" / "cat actions"). The shared `.table td` hairline is zeroed per table (`.rules-table`, `.tx-table`); a new card table must do the same.
- **The Budget plan only fills fields** and writes on Save plan (vermilion only when something changed). "Plan for" is this month or the next; next month shows its dates, has no income comparison (its last month is still running) and fills from the current plan. The choice is locked while anything is changed, so a change never hides in the other month. History means finished months outside `behind_months` that have spending. A saved amount applies from the planned month on; the note above the fields names it.
- **While something is changed** the count, the net change, Save plan and Undo sit in a raised bar that sticks to the foot of the panel (`.bud-actions.is-bar`, bottom at `--chat-fab-bottom`: above the tab slab, level with the chat button). It stops a chat button short on the right below 1100px, where the panel spans the page; beside Categories it ends well before the button. A save shows "Saved for N months" in the bar for a few seconds, then the plain disabled Save plan stays at the list's end. With nothing changed there is no bar.
- **Rule suggestions** need the same description put in one category by hand at least 3 times with no rule covering it; dismissals live in `localStorage`.
- **What a category counts as** is a select on its row in Categories. A category in use asks first (a browser confirm), then sends `force`.
- **Set-asides** reuse the `.setup-adj` row. "Mark as paid" opens a picker of money that went out, newest first. **Target split** is three numbers that must add up to 100; Save is off until they do.
- **Row controls match their row.** A category's type select is 2.25rem tall (`--tap` on touch) and 5.25rem wide so names keep room; a set-aside's delete is `btn btn-sm btn-danger setup-icon`, quiet until hover, like Rules and Categories.
- **Rules table on desktop** gives the category column 40% so names stay on one line; on a phone the table panel's side padding is 0.3rem so rows sit on the inset of the other Setup panels.
- **Small forms (`.setup-split`)**: on a phone the three percent fields share one row (a third each), own-account names take a row each, and Save fills the row; from 560px they sit in one line. Number fields are 6.5rem everywhere. The "which payment" form is one column with Paid and Cancel in a row under the select.
